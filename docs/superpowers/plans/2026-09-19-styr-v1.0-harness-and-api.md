# Styr v1.0 "Boring and durable" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. One card per worktree; the orchestrator merges.

**Goal:** A second harness (OpenAI Codex CLI) behind the same `Harness` interface, a stable
and versioned API with a published OpenAPI document and a changelog, an upgrade and backup
story, and roles for a handful of users. After v1.0 the API only changes additively within
the major version.

**Findings before planning (workstation, 2026-09-19):** `codex-cli 0.154.0` is installed.
`codex exec` runs non-interactively with `--json` (JSONL events on stdout), `--output-schema
<file>` (structured final answer), `-m <model>`, `-C <dir>`, `--sandbox read-only |
workspace-write | danger-full-access`, `--approve-for-me` (approvals answered by an automatic
reviewer, no host channel), `exec resume <id>` and `exec fork <id>`. There is no equivalent of
Claude Code's `--permission-prompt-tool stdio`: Codex approvals are a sandbox policy, not a
question the host can answer. Consequence: a Codex session in Styr is either **read-only**
(sandbox read-only, no approvals needed, maps to the `investigate` profile) or
**workspace-write** in a worktree (maps to `interactive`/`remediate` with the caveat that Styr
cannot approve individual commands; the inbox shows "Codex sessions apply the sandbox policy,
not per-command approvals"). Never `--dangerously-bypass-approvals-and-sandbox`, the same rule
as for Claude Code's bypass mode; CI greps for it.

## Cards

Wave 1 (parallel):
- **T60 Codex spike + harness**: record three `codex exec --json` fixtures (simple text; a
  file read; a workspace-write turn with `--output-schema`) with a recorder under
  `hack/codex-recorder`, document the event stream in
  `internal/harness/codex/testdata/PROTOCOL.md` (thread/turn ids, item events for messages,
  commands and file changes, the final `turn.completed` and where the structured output
  lands, how `resume` works and whether the process can take a second prompt over stdin or
  needs one process per turn), then implement `internal/harness/codex` behind
  `harness.Harness`: `Start` runs one process per turn (`exec` then `exec resume <thread>`
  for later turns) if stdin multi-turn is unsupported, `Decide` returns ErrUnsupported (no
  approvals), `Interrupt` kills the turn's process, `Events()` maps items to
  `text/tool_use/tool_result/result` (commands as tool_use "Bash", file changes as "Edit"),
  `Result.StructuredOutput` from the output schema file. Tests over fixtures and a shell fake
  `testdata/fake-codex/fake-codex.sh`.
- **T61 harness registry + per-workspace/session choice**: `harness.Registry` with kinds
  `claude` and `codex`; `Profile.Harness` default `claude`; sessions store `harness`
  (column exists); `POST /sessions` accepts `harness`; the Codex token is the user's own
  `codex login` under their Styr HOME (`users/<id>/.codex`), with a profile card "Sign in to
  Codex" that runs `codex login --device-auth`? spike: whether device auth works headless;
  otherwise the user pastes an API key into the profile (`OPENAI_API_KEY` sealed with the
  Box) and Styr passes it to the child. Codex sessions show a harness chip and hide the
  approval affordances; `investigate` profile enforces `--sandbox read-only`.
- **T62 API v1 freeze**: `docs/openapi.yaml` gets `info.version: 1.0.0` and every route a
  stable `operationId`; a `docs/API.md` overview; `GET /api/v1/version`; a `CHANGELOG.md`
  (Keep a Changelog) seeded from the git history v0.1.0 → v1.0.0; a CI job that fails when
  `docs/openapi.yaml` changes a non-additive way against the last tag (a small script
  comparing paths and required fields); deprecation policy written in `docs/API.md`.
- **T63 backup, upgrade and doctor**: `styr backup <file>` (SQLite online backup via
  `VACUUM INTO` plus a tar of `users/*/.claude` sizes? no: only the DB and the config
  references; worktrees and clones are re-creatable), `styr restore <file>` (refuses on a
  running server), doctor checks for disk space and orphan worktrees, `install.sh --version
  <v>` tested for downgrade refusal; docs.
- **T64 roles**: `viewer` role (read-only across the UI; cannot start sessions, approve, or
  edit); `member` unchanged; per-workspace access list for shared workspaces (admin picks
  users or "everyone"); API and UI; tests.

Wave 2: **T65 integration** (real-mode e2e for a Codex session through the fake, harness
switch in the new-session dialog, viewer role paths, backup/restore round trip), **T66 docs and
release** (`docs/HARNESSES.md`, README "Harnesses" section and the v1.0 announcement text,
roadmap "Beyond 1.0": Gemini CLI, multi-node runners, marketplace of templates), release v1.0.0.
