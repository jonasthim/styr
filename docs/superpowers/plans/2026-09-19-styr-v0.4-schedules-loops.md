# Styr v0.4 "Schedules and loops" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. One card per worktree; the orchestrator merges.

**Goal:** Keep going without a human: cron schedules start template runs on a cadence; loops
repeat a template until its report says done; a fleet Gantt shows where sessions spend time;
a cost dashboard shows what the whole box spends.

**Architecture:** New `internal/schedules` (cron table, next-run computation with
`robfig/cron/v3`, a scheduler goroutine that fires runs through the existing `runs.Engine`),
loops modelled as a `runs.Loop` record that chains runs on the same session (resume) until the
report's `until` field is truthy or `max_iterations` is reached, plus read-only stats
endpoints for the Gantt and the cost dashboard. Frontend: Schedules page, Loop builder inside
the template editor, Fleet Gantt toggle on the Sessions page, Cost page under Runs.

**Constraints:** as before. Schedules and loops are unattended: service token, the template's
profile, approvals expire to deny. A schedule never overlaps itself (skip with a delivery-like
record when the previous run is still running). Timezone: the server's, shown in the UI.

## Data model (migration `00006_schedules.sql`)

```sql
CREATE TABLE schedules (
  id TEXT PRIMARY KEY, owner_user_id TEXT REFERENCES users(id) ON DELETE CASCADE, name TEXT NOT NULL,
  template_id TEXT NOT NULL REFERENCES templates(id), cron TEXT NOT NULL, enabled INTEGER NOT NULL DEFAULT 1,
  vars TEXT NOT NULL DEFAULT '{}', last_run_at TEXT, last_outcome TEXT NOT NULL DEFAULT '', next_run_at TEXT,
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL);
CREATE TABLE schedule_firings (
  id TEXT PRIMARY KEY, schedule_id TEXT NOT NULL REFERENCES schedules(id) ON DELETE CASCADE, fired_at TEXT NOT NULL,
  status TEXT NOT NULL CHECK (status IN ('started','skipped_overlap','failed')), reason TEXT NOT NULL DEFAULT '', run_id TEXT);
CREATE TABLE loops (
  id TEXT PRIMARY KEY, template_id TEXT NOT NULL REFERENCES templates(id), session_id TEXT REFERENCES sessions(id) ON DELETE SET NULL,
  origin TEXT NOT NULL, origin_ref TEXT NOT NULL DEFAULT '', until_field TEXT NOT NULL DEFAULT 'done', max_iterations INTEGER NOT NULL DEFAULT 5,
  iteration INTEGER NOT NULL DEFAULT 0, state TEXT NOT NULL CHECK (state IN ('running','done','exhausted','failed','stopped')),
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL);
ALTER TABLE templates ADD COLUMN loop_until TEXT NOT NULL DEFAULT '';        -- '' = no loop; else the report field name
ALTER TABLE templates ADD COLUMN loop_max INTEGER NOT NULL DEFAULT 0;
ALTER TABLE runs ADD COLUMN loop_id TEXT REFERENCES loops(id);
ALTER TABLE runs ADD COLUMN iteration INTEGER NOT NULL DEFAULT 0;
```
`runs.origin` gains the value `schedule` and `loop`. `sessions.origin` already has `schedule`.

## Semantics

- **Schedule**: standard 5-field cron (robfig parser with `cron.SecondOptional` off), plus
  `@hourly`/`@daily` descriptors. On each tick (every 30 s) the scheduler loads enabled
  schedules whose `next_run_at <= now`, and for each: if a run started by this schedule is still
  running → firing `skipped_overlap`; else `runs.Engine.Start(RunInput{TemplateID, Origin:
  schedule, OriginRef: schedule id, Vars: schedule.vars merged with {"schedule": {name, fired_at}}})`
  → firing `started`; failures → `failed` with reason. Then `next_run_at` recomputed. `Run now`
  fires immediately regardless of cron. Only one scheduler runs (single process).
- **Loop**: a template with `loop_until` set makes every run started from it a loop: iteration
  1 is the normal run; when its report arrives and `report[loop_until]` is not truthy (missing,
  false, 0, "", "no") and `iteration < loop_max` → the engine sends the next prompt on the
  **same session** (`sessions.Send` with the rendered prompt plus a line "Iteration N of M.
  Previous report: <json>") and creates a new run row with `iteration` N; when truthy → loop
  `done`; when exhausted → `exhausted`; a failed run → `failed`. A loop can be stopped from the
  UI (`stopped`, the session is closed). Loops therefore reuse the session's context; the cost
  accumulates on the session.
- **Fleet Gantt data**: `GET /stats/gantt?from=&to=` → sessions active in the window with
  segments derived from the events table: `running` (between a user turn and its result),
  `waiting` (approval created → decided), `idle`. Computed on request, capped at 200 sessions.
- **Cost dashboard**: `GET /stats/costs?days=30` → totals per day, per user (owner) and per
  origin (ui, webhook, schedule, loop, pipeline), from `sessions.cost_usd` and `runs.cost_usd`;
  plus top templates by cost. Numbers are the CLI's `total_cost_usd` equivalents; the UI says
  "on your plan, shown as API-equivalent cost".

## API

```
GET/POST /schedules {name, template_id, cron, vars?, enabled?}   → Schedule (with next_run_at, last_run_at, last_outcome)
GET/PATCH/DELETE /schedules/{id}; POST /schedules/{id}/run → 202 {run_id}; GET /schedules/{id}/firings?limit=
POST /schedules/preview {cron} → {next: [5 timestamps], description}      (uses a cron-describer, hand-written for the common forms)
GET /loops?state=&limit= ; GET /loops/{id} (runs in order with reports) ; POST /loops/{id}/stop → 202
GET /stats/gantt?from=&to= ; GET /stats/costs?days=
Templates: `loop_until`, `loop_max` on create/patch and in responses.
Runs: `loop_id`, `iteration` in responses; RunView gains `loop`.
```

## Frontend

- **Schedules page** (`/schedules`, rail item with a clock icon): table (name, template, cron
  in mono with a human description, next run, last run with outcome glyph, enabled switch, Run
  now, firings drawer); create/edit dialog with a cron input, the 5-next-times preview, template
  select and a vars JSON editor with validation.
- **Loop builder** in the template editor: a "Loop" section with `until` field (select from the
  report schema's boolean fields, or free text) and max iterations; templates with a loop show a
  loop chip in lists. **Loops page** as a tab next to Runs: state, iteration N/M, template,
  session link, per-iteration reports as an accordion, Stop.
- **Fleet Gantt**: toggle on the Sessions page (`Gantt` segmented control); SVG lanes per
  session across the selected window (1 h, 6 h, 24 h), segments coloured by running/waiting/
  idle with hatched waiting, hover tooltip, click to open the session; live edge.
- **Cost page** (`/runs/costs`, tab under Runs): stat tiles (today, 7 d, 30 d), a bar chart per
  day (hand-rolled SVG, tokens only), breakdown tables by user and by origin, top templates.
- Run detail shows the loop iteration chip and a link to the loop.
