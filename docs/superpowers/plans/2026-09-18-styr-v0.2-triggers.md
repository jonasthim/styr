# Styr v0.2 "Triggers" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Each task is one card executed in its own git worktree; the orchestrator merges.

**Goal:** A Grafana alert (or any webhook, or a schedule later) starts an unattended Styr session
from a template, the session investigates under the `investigate` profile, and its structured
report lands in a Runs page and, optionally, in ntfy.

**Architecture:** New backend packages `templates` (Go text/template rendering of prompts from a
payload), `triggers` (inbound webhook router with secrets, dedupe, cooldown, storm cap,
delivery log), `runs` (run records tied to sessions, report extraction from the CLI's
structured output), `notify` (ntfy and generic outbound webhook). Sessions gain a JSON schema
and an appended system prompt. Frontend gains Runs, Triggers and Templates pages plus a
Notifications settings section.

**Spec:** `docs/specs/2026-09-18-styr-design.md` (shared interfaces section) plus this file.
Roadmap note: this release ships before diff review; diff review moves to v0.3.

## Global constraints

Same as `docs/superpowers/plans/2026-09-18-styr-v0.1.md` "Global Constraints" and "Frontend
conventions". Reuse the UI primitives in `web/src/components/ui/`. Never bypass permissions.
Unattended sessions always run with `owner = nil` (service token), the template's profile
(default `investigate`), and the existing approval timeout that denies by default.

## Data model (migration `00003_triggers.sql`)

```sql
CREATE TABLE templates (
  id TEXT PRIMARY KEY, owner_user_id TEXT REFERENCES users(id) ON DELETE CASCADE, name TEXT NOT NULL,
  workspace_id TEXT NOT NULL REFERENCES workspaces(id), profile_id TEXT NOT NULL REFERENCES profiles(id),
  title_template TEXT NOT NULL DEFAULT '', prompt_template TEXT NOT NULL, system_prompt TEXT NOT NULL DEFAULT '',
  report_schema TEXT NOT NULL DEFAULT '', created_at TEXT NOT NULL, updated_at TEXT NOT NULL);
CREATE UNIQUE INDEX templates_owner_name ON templates(COALESCE(owner_user_id,''), name);
CREATE TABLE triggers (
  id TEXT PRIMARY KEY, owner_user_id TEXT REFERENCES users(id) ON DELETE CASCADE, name TEXT NOT NULL, slug TEXT NOT NULL UNIQUE,
  kind TEXT NOT NULL CHECK (kind IN ('generic','grafana','github')), secret_hash TEXT NOT NULL, secret_hint TEXT NOT NULL DEFAULT '',
  template_id TEXT NOT NULL REFERENCES templates(id), enabled INTEGER NOT NULL DEFAULT 1,
  dedupe_key_template TEXT NOT NULL DEFAULT '', cooldown_s INTEGER NOT NULL DEFAULT 600, storm_cap_per_hour INTEGER NOT NULL DEFAULT 10,
  run_on_resolved INTEGER NOT NULL DEFAULT 0, created_at TEXT NOT NULL, updated_at TEXT NOT NULL, last_delivery_at TEXT);
CREATE TABLE deliveries (
  id TEXT PRIMARY KEY, trigger_id TEXT NOT NULL REFERENCES triggers(id) ON DELETE CASCADE, received_at TEXT NOT NULL,
  status TEXT NOT NULL CHECK (status IN ('accepted','deduped','cooldown','storm','rejected','failed','skipped')),
  reason TEXT NOT NULL DEFAULT '', dedupe_key TEXT NOT NULL DEFAULT '', payload TEXT NOT NULL, run_id TEXT);
CREATE INDEX deliveries_trigger_idx ON deliveries(trigger_id, received_at DESC);
CREATE TABLE runs (
  id TEXT PRIMARY KEY, session_id TEXT NOT NULL REFERENCES sessions(id) ON DELETE CASCADE, template_id TEXT REFERENCES templates(id),
  trigger_id TEXT REFERENCES triggers(id), delivery_id TEXT REFERENCES deliveries(id), origin TEXT NOT NULL,
  started_at TEXT NOT NULL, finished_at TEXT, outcome TEXT NOT NULL CHECK (outcome IN ('running','success','failed','timeout','needs_human')),
  report TEXT NOT NULL DEFAULT '', summary TEXT NOT NULL DEFAULT '', cost_usd REAL NOT NULL DEFAULT 0);
CREATE INDEX runs_started_idx ON runs(started_at DESC);
CREATE TABLE notification_channels (
  id TEXT PRIMARY KEY, kind TEXT NOT NULL CHECK (kind IN ('ntfy','webhook')), name TEXT NOT NULL, url TEXT NOT NULL,
  token_ciphertext BLOB, token_nonce BLOB, events TEXT NOT NULL DEFAULT '["run.finished","run.needs_human","run.failed"]',
  enabled INTEGER NOT NULL DEFAULT 1, created_at TEXT NOT NULL);
CREATE TABLE api_tokens (
  id TEXT PRIMARY KEY, user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE, name TEXT NOT NULL, token_hash TEXT NOT NULL UNIQUE,
  prefix TEXT NOT NULL, created_at TEXT NOT NULL, last_used_at TEXT, expires_at TEXT);
```

Secrets: trigger secrets are generated by Styr (32 random bytes, base64url, prefix `styr_whs_`),
shown once, stored as sha256. API tokens: `styr_pat_` prefix, same scheme as valheim-server-ui.
ntfy tokens are sealed with the existing `crypto.Box`.

## API contract (`/api/v1`, cookie or `Authorization: Bearer styr_pat_…`)

```
GET/POST /templates            {name, workspace_id, profile_id, title_template, prompt_template, system_prompt, report_schema}
GET/PATCH/DELETE /templates/{id}
POST /templates/{id}/render    {payload} → {title, prompt, errors[]}     (dry run)
GET/POST /triggers             {name, kind, template_id, dedupe_key_template?, cooldown_s?, storm_cap_per_hour?, run_on_resolved?}
                               POST → 201 {trigger, secret}  (secret only in this response)
GET/PATCH/DELETE /triggers/{id}; POST /triggers/{id}/rotate-secret → {secret}
GET /triggers/{id}/deliveries?limit=50 ; POST /deliveries/{id}/replay → 202 {run_id?}
POST /triggers/{id}/test       {payload} → runs the full pipeline as if delivered (respects dedupe unless {"force":true})
GET /runs?outcome=&trigger=&limit= ; GET /runs/{id} (includes session summary, report, delivery)
GET/POST /notifications        {kind, name, url, token?, events[]} ; PATCH/DELETE /notifications/{id}; POST /notifications/{id}/test
GET/POST /me/api-tokens        {name, expires_in_days?} → 201 {token (once), id, prefix} ; DELETE /me/api-tokens/{id}
POST /hooks/{slug}             inbound, no cookie auth, outside CSRF; auth by header `X-Styr-Secret: <secret>` or
                               `Authorization: Bearer <secret>`; GitHub kind uses `X-Hub-Signature-256` HMAC over the raw body.
                               Responses: 202 {delivery_id, status, run_id?}; 401 bad secret; 404 unknown/disabled; 413 body > 256 KiB.
```

Visibility: templates and triggers belong to a user or are shared (owner null, admin-created).
Runs are visible to everyone (unattended) per the v0.1 decision; deliveries follow their trigger.

## Template rendering

Go `text/template` with `missingkey=zero`, functions: `lower`, `upper`, `join`, `default`,
`truncate n`, `json`, `now`. Variables: the raw payload as `.payload`, plus normalised
fields per kind. Grafana (Alertmanager-compatible webhook): `.status` (firing|resolved),
`.alerts` (list of {status, labels, annotations, startsAt, endsAt, fingerprint, generatorURL,
silenceURL, dashboardURL, panelURL, values}), `.commonLabels`, `.commonAnnotations`,
`.groupLabels`, `.title`, `.message`, `.externalURL`. Default dedupe key for grafana:
`{{ .status }}:{{ range .alerts }}{{ .fingerprint }},{{ end }}`. Default prompt for grafana
(seeded template "Grafana alert investigation", shared, profile investigate):

```
A Grafana alert is {{ .status }}. Investigate read-only and report.
{{ range .alerts }}- {{ .labels.alertname }} on {{ default "unknown" .labels.instance }}: {{ .annotations.summary }}
  {{ .annotations.description }} (since {{ .startsAt }})
{{ end }}
Use the workspace's runbooks and only read-only commands. Do not change anything.
```

Report schema seeded for it: `{"type":"object","required":["severity","diagnosis","proposed_action","confidence"],
"properties":{"severity":{"enum":["info","warning","critical"]},"diagnosis":{"type":"string"},
"evidence":{"type":"array","items":{"type":"string"}},"proposed_action":{"type":"string"},
"confidence":{"type":"number","minimum":0,"maximum":1},"resolved_itself":{"type":"boolean"}}}`.

## Run engine

`runs.Engine.Start(ctx, RunInput{TemplateID, TriggerID, DeliveryID, Vars})`: render title and
prompt, create the session via `sessions.Service.Create` with `Owner nil`, `Origin webhook`,
`OriginRef run id`, `JSONSchema` and `SystemPrompt` from the template (new `CreateInput`
fields → `StartSpec.JSONSchema`, `StartSpec.SystemPrompt` → CLI flags `--json-schema`,
`--append-system-prompt`). Insert the run with outcome running. The engine subscribes to the
bus: on `session.state` failed → outcome failed; on the session's result event with
`structured_output` → parse into report, `summary` = report.diagnosis (first 200 chars) or
result text, outcome success; on approval created for an unattended session → outcome stays
running but `needs_human` is published as an event for notifications; on approval expired →
outcome needs_human when the session ends without a report. A run older than
`run_timeout` (default 30 min) still running is closed as timeout (interrupt + close the session).

## Notifications

`notify.Service.Publish(event Event)` where Event has Kind (`run.finished`, `run.needs_human`,
`run.failed`), Title, Body, URL (deep link to the run), Priority. Channels: ntfy (`POST
<url>` with headers Title, Priority, Tags, Click, Authorization Bearer when a token is set) and
generic webhook (`POST <url>` JSON body of the Event with `X-Styr-Event`). 10 s timeout,
one retry, every attempt logged at info; failures never affect the run.

## Frontend

- **Runs page** (`/runs`): table rows: outcome glyph, title, trigger, started, duration, cost;
  filter chips by outcome; detail drawer or page `/runs/$id`: report rendered from the
  template's schema (severity badge, diagnosis, evidence list, proposed action, confidence
  meter), link to the session, the delivery payload collapsed, "Re-run".
- **Triggers page** (`/triggers`): list with kind chip, template, enabled switch, last delivery,
  deliveries drawer with status chips and replay; create dialog with kind selector, template
  select, advanced fields; after create show the webhook URL and the secret once with copy
  buttons and a Grafana contact-point snippet; "Send test payload" with a per-kind sample.
- **Templates page** (`/templates`): editor with variables help, live "Render with sample"
  preview, schema editor with validation.
- **Settings → Notifications**: channels table, add ntfy/webhook, test button.
- **Profile → API tokens**: create (shown once), list, revoke.
- Rail: add Runs and Triggers; Templates lives under Triggers as a tab. Session view header
  shows an "Unattended run" chip linking to the run.
