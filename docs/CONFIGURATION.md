# Configuration

Styr reads `config.yaml` (path from `STYR_CONFIG`, or none — every field then falls back to its
default), then applies `STYR_*` environment overrides on top, then validates the result. A
missing config file is not an error: defaults plus environment variables are enough to run in
`dev` mode. See `deploy/config.example.yaml` for a commented starting point and
`internal/config/config.go` for the authoritative source.

## Keys

| `config.yaml` key | Env override | Default | Notes |
|---|---|---|---|
| `env` | `STYR_ENV` | `prod` | `prod` or `dev`. Only `dev` honours `dev_user` and skips the `base_url`/`oidc` requirements below. |
| `listen` | `STYR_LISTEN` | `127.0.0.1:8080` | Address the HTTP server binds to. |
| `base_url` | `STYR_BASE_URL` | *(none)* | Public URL users reach Styr at. Required in `prod`; used to build the OIDC redirect URI (`<base_url>/api/v1/auth/callback`). |
| `data_dir` | `STYR_DATA_DIR` | `/var/lib/styr` (prod), `./data` (dev) | Directory for the SQLite database, per-user data and workspace checkouts. See [Data directory layout](#data-directory-layout). |
| `secret_key` | `STYR_SECRET_KEY` | *(none)* | 32+ bytes, base64 or raw. Encrypts stored Claude tokens at rest. Required. Generate with `openssl rand -base64 32`. |
| `claude_bin` | `STYR_CLAUDE_BIN` | `claude` | Path to the Claude Code CLI binary. |
| `max_open_sessions` | `STYR_MAX_OPEN_SESSIONS` | `4` | Maximum number of concurrently open Claude sessions (a slot semaphore; further sessions queue). |
| `idle_timeout` | `STYR_IDLE_TIMEOUT` | `15m` | How long an open session may sit idle before it is closed automatically. |
| `approval_timeout` | `STYR_APPROVAL_TIMEOUT` | `30m` | How long an unattended profile waits for approval before the request expires (defaults to deny). |
| `oidc` | *(list, see below)* | *(none)* | One or more OpenID Connect providers shown on the login page. Required in `prod` (at least one). |
| `dev_user` | `STYR_DEV_USER` | *(none)* | Email of the synthetic logged-in user used when `env` is `dev`. Ignored in `prod`. |

`oidc` is a list of providers; each has its own fields and does not have a single flat env
override, with one exception:

| `oidc[i]` field | Notes |
|---|---|
| `name` | Shown on the login button, e.g. `Authentik`. |
| `issuer` | The provider's OIDC issuer URL, used for discovery. |
| `client_id` | OAuth client ID registered with the provider. |
| `client_secret` | Optional for a public client (PKCE-only). `STYR_OIDC_CLIENT_SECRET` always fills provider `0`'s secret, so a single-provider deployment can keep the secret out of `config.yaml` entirely. |
| `scopes` | Defaults to `[openid, profile, email]` when omitted. |

`STYR_*` values always win over `config.yaml`. Durations use Go's `time.ParseDuration` syntax
(`15m`, `1h30m`, `30s`).

## Tokens

Styr uses two distinct kinds of Claude token:

- **Per-user token.** Every user pastes their own token, generated by running
  `claude setup-token` on any machine where they're already logged into Claude Code, into their
  profile in the Styr UI. It is verified, then encrypted at rest with `secret_key`; the API
  never returns the raw token again, only its verification status and a 6-character suffix
  label. Sessions a user starts bill that user's own Claude plan, and each user's Claude CLI
  state lives under its own `HOME` (see below) so tokens and settings never cross between users.
- **Service token.** An admin sets a separate token under Settings for unattended runs
  (`owner_user_id` is null) — webhooks, schedules and pipelines in later releases. It is stored
  and verified the same way as a per-user token, but is not tied to any one member.

## Profiles

A profile bundles the settings a session starts with: workspace, permission mode and
allow/deny tool lists, plus (from v0.2) worktree behaviour. Profiles are configured in the UI
under Settings (admin) and picked per-session from the Sessions and Inbox screens; there is no
`config.yaml` key for them in v0.1.

## Data directory layout

Everything Styr owns lives under `data_dir`:

```
<data_dir>/
  styr.db              SQLite database: sessions, events, approvals, users, audit log
  users/<user-id>/      one directory per user, used as that user's Claude CLI HOME
                         (keeps ~/.claude state, credentials and settings isolated per user)
  workspaces/<name>/    registered workspace checkouts sessions run against
```

`internal/config/config.go`'s `DBPath()`, `UsersDir()` and `WorkspacesDir()` are the
authoritative paths (`<data_dir>/styr.db`, `<data_dir>/users`, `<data_dir>/workspaces`).
